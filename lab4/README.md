## 1. Загальний опис проєкту

У межах лабораторної роботи №4 на базі Laravel 13 розроблено повнофункціональний ресурсний **REST HTTP API** для керування сутностями каталогу комп’ютерної техніки — **Продуктами** (`Product`) та **Категоріями** (`Category`). 

Застосунок розгорнуто в ізольованому середовищі **Docker Compose** (проєкт `lab4`, порт `8081`, окремий том бази даних `MySQL 8.4`). Документування API та інтерактивний вебінтерфейс тестування реалізовано за допомогою пакета **Dedoc Scramble** згідно зі специфікацією **OpenAPI 3.1.2**.

## 2. Архітектура та розподіл відповідальності

Взаємодія побудована на чіткому поділі шарів застосунку:

```
HTTP-запит ──> Route (apiResource)
                 └──> Form Request (валідація правил і типів)
                        └──> Controller (координація операції)
                               └──> Service (бізнес-логіка, контроль цілісності, Eloquent)
                                      └──> API Resource (трансформація у регламентований JSON)
```

1. **Маршрутизація (`routes/api.php`):**
   - Використано `Route::apiResource()` для реєстрації операцій `index`, `store`, `show`, `update`, `destroy` з префіксом імен `api.*`.
   - Збережено наявні маршрути каталогу лабораторної №3 (`/api/catalog`, `/api/catalog/{slug}`).
   - Підключено автоматичний Route Model Binding для параметрів `{product}` і `{category}`.

2. **Валідація вхідних даних (`app/Http/Requests/Api/*`):**
   - `StoreProductRequest` та `StoreCategoryRequest` перевіряють обов'язковість і типи полів при створенні.
   - `UpdateProductRequest` та `UpdateCategoryRequest` реалізують підтримку часткових змін (**PATCH**) за допомогою правила `sometimes`.
   - `decimal:0,2` обмежує точність грошових сум (до 2 знаків після коми), `exists:categories,id` гарантує наявність батьківської категорії, а `Rule::unique()->ignore()` виключає поточну модель під час перевірки унікальності `slug`.

3. **Сервісний шар (`app/Services/*`):**
   - `ProductService` інкапсулює логіку наповнення системних значень за замовчуванням та роботу з моделями.
   - `CategoryService` реалізує захист посилальної цілісності: спроба видалення категорії, що містить прив'язані товари, породжує виняток `CategoryNotEmpty`.

4. **Обробка винятків та помилок (`bootstrap/app.php`):**
   - Метод `shouldRenderJsonWhen()` гарантує примусове повернення відповідей виключно у форматі JSON для всіх адрес `/api/*`.
   - Виняток `CategoryNotEmpty` перехоплюється та трансформується у регламентовану відповідь **`409 Conflict`**.
   - Відсутність запису (`ModelNotFoundException`) повертає уніфікований JSON зі статусом **`404 Not Found`**.
   - Помилки валідації повертають статус **`422 Unprocessable Content`** із докладним масивом `errors`.

5. **Трансформація ресурсів (`app/Http/Resources/*`):**
   - `ProductResource` явно форматує ціну як десятковий рядок із двома знаками після коми (`number_format((float) $this->price, 2, '.', '')`) для суворої відповідності схемі OpenAPI.
   - `CategoryResource` регламентує структуру категорії та дати у форматі ISO 8601.

## 3. Контракт кінцевих точок REST API

| Метод | Маршрут | Опис операції | Тіло / Параметри | Статус успіху | Можливі помилки |
|---|---|---|---|:---:|:---:|
| `GET` | `/api/categories` | Список усіх категорій | `page` | `200 OK` | `500` |
| `POST` | `/api/categories` | Створення нової категорії | JSON: `name`, `slug` | `201 Created` *(Location)* | `422` |
| `GET` | `/api/categories/{category}` | Читання категорії за ID | ID у шляху | `200 OK` | `404` |
| `PUT` / `PATCH` | `/api/categories/{category}` | Оновлення категорії | JSON: `name`, `slug` | `200 OK` | `404`, `422` |
| `DELETE` | `/api/categories/{category}` | Видалення категорії | ID у шляху | `204 No Content` | `404`, `409` |
| `GET` | `/api/products` | Список продуктів | `page` | `200 OK` | `500` |
| `POST` | `/api/products` | Створення нового продукту | JSON: `title`, `slug`, `price`, `category_id`... | `201 Created` *(Location)* | `422` |
| `GET` | `/api/products/{product}` | Деталі продукту за ID | ID у шляху | `200 OK` | `404` |
| `PUT` / `PATCH` | `/api/products/{product}` | Часткове/повне оновлення | JSON: `price`, `title`... | `200 OK` | `404`, `422` |
| `DELETE` | `/api/products/{product}` | Видалення продукту | ID у шляху | `204 No Content` | `404` |
| `GET` | `/api/catalog` | Вибірка каталогу (з фільтрами) | `q`, `category`, `operation`, `sort`, `page`, `per_page` | `200 OK` | `422` |
| `GET` | `/api/catalog/{slug}` | Читання продукту за slug | slug у шляху | `200 OK` | `404` |

## 4. Швидкий старт і запуск у Docker

Усі команди Docker виконуються в терміналі хост-системи з каталогу `lab4`.

### 4.1. Налаштування середовища та запуск контейнерів
```bash
# 1. Створення файлу конфігурації
cp .env.example .env

# 2. Перевірка та запуск мультиконтейнерного стенда lab4
docker compose config --quiet
docker compose up -d

# 3. Перевірка готовності MySQL (очікувати "ready for connections" на порті 3306)
docker compose logs mysql

# 4. Вхід у термінал застосунку
docker compose exec --user application app sh
```

### 4.2. Ініціалізація застосунку (всередині контейнера у `/app`)
```bash
# Встановлення PHP-залежностей
composer install

# Генерація ключа застосунку та скидання кешів
php artisan key:generate
php artisan config:clear

# Застосування міграцій та наповнення початковими даними (4 категорії, 12 товарів)
php artisan migrate --seed

# Перевірка списку зареєстрованих маршрутів API
php artisan route:list --path=api
```

### 4.3. Генерація специфікації OpenAPI
```bash
# Експорт актуальної машиннозчитуваної специфікації у корінь проєкту
php artisan scramble:export --path=api.json
```

### 4.4. Зупинка контейнерів
```bash
# Зупинка без втрати даних MySQL
docker compose stop
```
*(Примітка: команда `docker compose down -v` повністю знищує volume з базою даних).*
