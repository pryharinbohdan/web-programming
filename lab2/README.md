## 1. Обґрунтування вибору теми оформлення

Для предметної області **«Продаж комп’ютерної техніки»** ключовим фактором вибору для користувача є швидкий доступ до технічних характеристик пристрою (процесор, обсяг RAM, накопичувач SSD, частота екрана чи інтерфейси). 

Тема **`tech-showcase`** ідеально адаптована для такого каталогу:
1. **Інформаційна щільність:** Блок специфікацій (`.tech-card__specs`) винесений безпосередньо в картку каталогу, що дозволяє порівнювати моделі без необхідності переходу на сторінку кожного товару.
2. **Маркування та акценти:** Бейджі (`.tech-card__label`) одразу відображають цільове призначення пристрою («Хіт продажу», «Для ігор», «Для дизайну»).
3. **Стилістика:** Стримана технологічна кольорова гама (відтінки cyan, indigo, violet) та моноширинні шрифтові акценти підкреслюють інженерну спрямованість магазину.

## 2. Архітектура та технічні рішення

### 2.1. Ланцюжок «Маршрут → Контролер → Сервіс → Blade»
- **Маршрутизація (`routes/web.php`):** Реєструє чітко типізовані іменовані маршрути:
  - `home` (`/`) — обробляється `HomeController@index`;
  - `catalog.index` (`/catalog`) — обробляється `CatalogController@index`;
  - `catalog.show` (`/catalog/{slug}`) — обробляється `CatalogController@show`.
- **Впровадження залежностей (Dependency Injection):** Сервіс `CatalogService` автоматично інстанціюється контейнером служб Laravel через параметри конструкторів `HomeController` і `CatalogController`.
- **Ізоляція логіки:** Контролери не формують HTML і не містять генерації даних. Їхня відповідальність обмежена викликом методів сервісу, передачею колекцій у представлення або викиданням винятку `abort(404)` у разі відсутності запитаного slug.

### 2.2. Сервісний шар і детермінованість даних
- Клас `App\Services\CatalogService` інкапсулює логіку читання профілю з `config/catalog.php`.
- Використовується генератор `Faker` з українською локаллю `uk_UA` та фіксованим seed для 9-го варіанта (`seed = 2109`). Це гарантує ідемпотентність: після будь-якого перезапуску сервера чи скидання кешу генерується ідентичний набір із 12 карток.
- Поле `slug` формується стабільно з назви через `Str::slug()`. У разі колізій додається числовий постфікс (динамічні значення часу `microtime()` або випадкові UUID не використовуються).

### 2.3. BEM-методологія та єдиний Data-інтерфейс
- Оформлення дотримується ієрархії Блок-Елемент-Модифікатор: `.site-header` → `.site-header__brand`, `.catalog-card` → `.catalog-card--featured`, `.notification-menu__item--unread`, `.button--cyan`.
- **Спільні контракти інтерфейсу:**
  - Кнопка замовлення: `data-action="request"`, `data-endpoint="/api/requests"`, `data-item="{slug}"`.
  - Меню сповіщень: `data-component="notification-center"`, `data-endpoint="/api/notifications"`, `data-notification-list`, події `mark-read` та `mark-all-read`.
  - Логіка взаємодії клієнта реалізована чистим локальним JS (`public/js/notifications.js`, `public/js/partners.js`) без додаткових бібліотек і залежностей від зовнішніх серверів.

## 3. Локальний запуск і перевірка

### Кроки запуску
```bash
# 1. Клонування репозиторію
git clone https://github.com/pryharinbohdan/web-programming.git
cd web-programming/lab2

# 2. Встановлення залежностей
composer install

# 3. Налаштування оточення
cp .env.example .env
php artisan key:generate

# 4. Запуск вбудованого сервера
php artisan serve
```
